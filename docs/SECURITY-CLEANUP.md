# Security Cleanup 0.2.0

## 調査と実装方針

既存のOPClientには、シェルを介さないProcess起動、JSON配列・連続JSON対応、50件単位の取得、最大3並列、120秒タイムアウト、中断機構があります。これを再利用しました。既存のEntryはURLごとに展開されTOTP・メモも持つため、Security Cleanupの入力・表示・保存には使用しません。

最小限の変更で、CLIにLOGIN専用読み取り経路を追加し、Cleanup.swiftに分析と対応記録、CleanupView.swiftに画面を分離しました。既存画面はタブに移動し、CSV比較・並べ替え・詳細表示を維持しています。読み取り専用の要件に合わせ、この版では既存画面の移行ボタンとModelの移行実行も無効です。OPClientの旧作成メソッドは互換用コードとして残りますが、UIから呼ぶ経路はありません。変更・削除・アーカイブ・自動変更は新設していません。

実装順は、LOGIN専用取得 → メモリ内の再利用・重複分析 → 状態保存 → 画面と再比較 → ダミーCLIによる検証です。

## 使い方

1. Security Cleanupタブの「ダミーデータ」を選ぶ。メール・ショップ・重複候補・クラウド管理の例で、行選択・絞り込み・状態変更を試す。ダミー操作の記録はディスクへ保存しません。
2. CLIの絶対パス、アカウントID、保管庫IDを入力。複数保管庫IDはカンマ・空白・改行で区切ります。同じアカウント内の保管庫を対象とします。
3. 「読み取り・再比較」を実行。対象保管庫ごとの進捗を表示します。認証失敗・タイムアウト・欠落・不正形式・中断時は全体を失敗にし、部分結果を採用しません。以前の分析結果もクリアして古い判定を見せません。対応記録は残ります。
4. 重要優先の一覧で項目を選びます。再利用グループ、同一ホスト・ユーザー名の重複候補、IDの大文字小文字が異なる候補を確認します。
5. 分類をメール・金融・ドメイン管理・クラウド管理・その他から修正し、現役・重要・退会済み・調査中・アーカイブ候補・対応完了を記録します。退会済みやアーカイブ候補はローカルのラベルで、サービスや1Passwordを変更しません。
6. 実際の変更はサービスと1Passwordで手動で行います。変更後に再取得すると、同じアイテムIDの対応記録を保持して現在の再利用・簡易強度を再計算します。同じ起動中の前回リスク要約との差を表示します。パスワード自体が変わったかを直接検証する機能ではありません。完了済みでも現在のリスク候補は隠しません。
7. 「結果を閉じる」で分析結果を解放します。再起動後は対応記録のみ復元し、分析には再取得が必要です。

## 分析と限界

- パスワードはUTF-8バイト列で厳密にグループ化します。空のパスワードは再利用対象外で、パスキーのみの項目などを弱いパスワードと誤認しません。再利用グループ番号は分析ごとに付け直す表示用番号です。
- URLはホストだけを取り出し、パス・クエリ・URL内の資格情報を表示モデルに残しません。ホストと同じユーザー名を持つ別アイテムを重複候補とし、別ホストの同じパスワードとは分けます。ユーザー名の大文字小文字差は別の関連候補です。
- 同じサービスでも別サブドメイン・別ドメインは自動統合しません。ホスト数は厳密なサービス数ではありません。1件に複数URLがある場合も、実際のアイテムIDを基準に1件と数えます。
- 簡易強度は10文字未満、異なる文字が3種以下、一部の典型的な語を弱い候補にし、14文字未満を要確認とします。辞書攻撃耐性や漏洩を網羅するものでも、Watchtowerやzxcvbnと一致するものでもありません。「警告なし」は安全の証明ではありません。
- 重要分類は少数の既知ホストによる提案です。すべての金融機関や管理用ログインを検出するものではありません。ユーザーの修正を優先します。
- 未取得保管庫・アーカイブ・LOGIN以外の項目は対象外です。別保管庫に残るパスワードを変更すると、再利用グループの件数が変わる可能性があります。

## 秘密情報の境界

CleanupLoginはCodableにせず、一時的に秘密を含む入力だけに使います。CLIの完全な項目応答には他の秘密が含まれる可能性がありますが、解析経路はusername/password/URL/ID/titleのみを取り出し、TOTP・メモ・復旧コードを表示・保存しません。パスワードの辞書キーは分析中のみ存在し、表示用CleanupRowには秘密や秘密のハッシュを持たせません。Swift・OS・1Passwordプロセスのメモリやスワップの確実なゼロ消去を保証する実装ではありません。

アプリに分析ログやレポート出力機能はありません。CLIのstderrを表示せず、JSON構文エラーにも生データを含めません。CLIプロセスではOP_DEBUGとOP_CACHEをfalseに固定し、アプリが診断出力やCLIキャッシュを有効にしないようにしています。1Password自身が管理する通常の保存・同期は別です。外部APIへ秘密やハッシュを照合しません。

対応記録は `~/Library/Application Support/PasswordBridge/cleanup-records.json` に保存します。キーはアカウントID・保管庫ID・アイテムIDの組み合わせ、値は固定選択の状態・分類・日時と最大30件の状態変更履歴だけです。タイトル・URL・ユーザー名・秘密・自由記述は保存しません。ディレクトリ0700、ファイル0600、アトミック書き込みです。保存失敗時は画面の記録も更新せず、壊れた保存ファイルは上書きしません。アイテムを別保管庫へ移動した場合は新しいスコープになり、記録を自動転記しません。

## Watchtowerの公式仕様調査

2026-11-03に以下の公式文書とインストール済みCLI 2.41.1のhelpを確認しました。

- [CLI command reference](https://www.1password.dev/cli/reference/)
- [item list/get reference](https://www.1password.dev/cli/reference/management-commands/item)
- [Watchtower privacy](https://support.1password.com/watchtower-privacy/)

公開CLIのコマンド・フラグにはWatchtowerの漏洩判定やスコアを取得する方法を確認できませんでした。この調査から、画面では「未対応・Watchtowerで確認」としています。将来のCLIで不可能だと断定するものではありません。Watchtower本体の漏洩照合を再実装したり、非公開API・内部データベースを読むことはしていません。

## 検証

`swift run BridgeChecks` で既存11テスト群とCleanupChecksを実行します。実際の保管庫や秘密は使用していません。

- 複数保管庫・同一IDのスコープ分離、再利用・同一アカウントの重複・別ID・大小文字差の区別
- 空パスワードの除外、Unicode正規化が異なる秘密の区別、変更後の再利用件数の減少
- 簡易強度、重要ホスト提案と似せた別ドメインの誤分類防止
- 記録の再読込・履歴・保存内容の許可フィールド・壊れた記録の保持
- 模擬CLIでitem list/getのみを許可し、Loginフィルターとデバッグ・キャッシュ無効を確認
- CLI失敗・不正カテゴリ・中断、表示モデルにパスワード・TOTP・URLクエリを残さないこと
- 既存の一括取得で欠落・失敗・タイムアウト時に不完全な結果を採用しないこと

GUIの操作確認と実環境の認証・通信速度の検証は別途必要です。実データのパスワード変更・削除・アーカイブは実施していません。
